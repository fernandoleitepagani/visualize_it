Complexidade de Algoritmos

Contagem de operações, funções de custo e notações assintóticas

Por que medir o custo de um algoritmo?

Um algoritmo pode ser correto e ainda assim ser inútil na prática — basta que ele leve séculos para terminar. Antes de escolher entre duas soluções, precisamos comparar quanto cada uma consome de tempo e de memória conforme o tamanho da entrada n cresce.

Essa medição é feita através de uma função de complexidade, que conta operações relevantes (comparações, movimentações, somas) sem se prender a detalhes de hardware ou de compilador.

Contagem de operações

A ideia central é simples: para cada trecho do código, somamos quantas vezes a operação de interesse acontece.

Condicional

O custo é o da condição mais o da lista executada. Melhor caso é o mínimo entre os dois ramos; pior caso é o máximo.

if (a - 5 < b - 3 || c - 1 < d - 3) {
  i--; --b; a -= 3;      // 4 subtrações
} else {
  j--;                    // 1 subtração
}

Melhor caso: 5 subtrações. Pior caso: 7 subtrações (o operador || curto-circuita quando a primeira condição é verdadeira).

Repetição simples

Um laço for (i = 0; i < n; i++) executa o corpo n vezes. Se o corpo faz 2 subtrações, o total é 2n.

Laço duplo

for (i = 0; i < n; i++)
  for (j = 0; j < n; j++)
    a--;                    // n·n = n² operações

Laço logarítmico

Quando o contador é dividido por 2 a cada passo, o número de iterações é ⌊lg n⌋ + 1:

for (i = n; i > 0; i /= 2)
  a *= 2;

Notações assintóticas

Contar operações exatas é útil, mas o que realmente importa é como a função cresce. As notações assintóticas capturam essa tendência — ignoram constantes e termos de menor grau.

Notação Θ — limite justo

g(n) é Θ(f(n)) se existem constantes positivas c₁, c₂ e m tais que, para todo n ≥ m:

c₁ · f(n) ≤ g(n) ≤ c₂ · f(n)

Ou seja, g é limitada por f tanto por baixo quanto por cima.

Notação O — limite superior

g(n) é O(f(n)) se existe c > 0 e m > 0 tais que, para todo n ≥ m:

|g(n)| ≤ c · |f(n)|

É um teto assintótico — diz que a função não cresce mais rápido que f.

Notação Ω — limite inferior

g(n) é Ω(f(n)) se existe c > 0 e m > 0 tais que, para todo n ≥ m:

|g(n)| ≥ c · |f(n)|

É um piso assintótico — diz que a função cresce pelo menos como f.

Relação entre as três

g(n) é Θ(f(n))   ⇔   g(n) é O(f(n))  e  g(n) é Ω(f(n))

Regras práticas

  • Ignore constantes multiplicativas: 3n², 5n² e n² são todas Θ(n²).
  • Ignore termos de menor grau: 3n + 2n² é Θ(n²); lg n + n é Θ(n).
  • O e Ω são independentes: uma função pode ser O(n³) e Ω(n) ao mesmo tempo — só Θ exige casamento dos dois.

Exemplo completo

Seja g(n) = 3n² + 5n + 1. Afirmações:

  • g(n) é O(n²) — verdadeira (basta c = 4, m = 5).
  • g(n) é O(n³) — verdadeira (afrouxar o teto é permitido).
  • g(n) é Ω(n²) — verdadeira.
  • g(n) é Ω(n³) — falsa (a função não cresce tão rápido).
  • g(n) é Θ(n²) — verdadeira, é a caracterização justa.

Operações válidas

f(n) = Θ(f(n))
c · Θ(f(n)) = Θ(f(n))
Θ(f(n)) + Θ(f(n)) = Θ(f(n))
Θ(f(n)) + Θ(g(n)) = Θ(max(f(n), g(n)))
Θ(f(n)) · Θ(g(n)) = Θ(f(n) · g(n))

As mesmas regras valem para O e Ω.

Algoritmos polinomiais × intratáveis

Um algoritmo é polinomial se seu custo é Θ(nᵖ) para algum inteiro p. Problemas que admitem solução polinomial são considerados tratáveis. Problemas para os quais nenhum algoritmo polinomial é conhecido — como o Caixeiro Viajante na formulação exata — são chamados de intratáveis.

O limite Ω(n lg n) vale para qualquer algoritmo de ordenação que decida apenas por comparações entre chaves. Algoritmos como counting sort escapam desse limite ao ordenar pelo valor das chaves, não por comparação.
